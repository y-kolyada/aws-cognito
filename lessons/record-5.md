## Что сделано

1. **Разработка и интеграция полного ансамбля из 17 адаптивных векторных схем с уникальными визуальными топологиями:**
   - По замечанию Архитектора о монотонности и сходстве схем («близнецы-братья») произведена глубокая визуальная и пространственная переработка всех 17 схем: ни одна схема курса не повторяет геометрию другой. Каждая схема спроектирована под специфику инженерной логики конкретного раздела:
     - `ru/index.html` · **Схема 1. Архитектурная модель сервиса: User Pools (каталог и токены) против Identity Pools (роли STS)** · *Топология: двухплоскостная архитектурная карта (Two-Plane Map)*. Четкое физическое разделение левой плоскости User Pools (CIAM, каталог, JWT токены) и правой плоскости Identity Pools (обмен на ключи STS, роли IAM Auth/Guest, доступ к S3 и DynamoDB).
     - `ru/01.html` · **Схема 2. Анатомия каталога User Pool: структура атрибутов, политики паролей и верификация** · *Топология: трехколонный компонентный разбор (3-Pillar Breakdown)*. Верхнее ядро каталога разветвляется на три независимых столпа (Схема атрибутов, Политики сложности и MFA, Каналы доставки OTP через SES/SNS) с конвергенцией в итоговое подтвержденное состояние CONFIRMED.
     - `ru/02.html` · **Схема 3. Триада токенов OIDC и OAuth 2.0: ID, Access, Refresh и проверка JWKS** · *Топология: замкнутый круговой контур (Circular Renewal Loop)*. Клиентское приложение отправляет токен в API Gateway, при ошибке 401 обращается в эндпоинт ротации /oauth2/token, обновляет токен из защищенного хранилища и возвращается в рабочий цикл без разлогина пользователя.
     - `ru/03.html` · **Схема 4. Поток Authorization Code с криптографическим протоколом PKCE** · *Топология: протокольная лестница обмена (Sequence Ladder)*. Две вертикальные колонки (Публичный клиент SPA и Сервер Cognito) с четырьмя строго горизонтальными шагами обмена (/authorize с code_challenge, редирект с code, /token с code_verifier, выдача токенов JWT).
     - `ru/04.html` · **Схема 5. Топология Hosted UI: CloudFront, ACM в us-east-1 и кастомный домен** · *Топология: 4-уровневый инфраструктурный стек (Tiered Infrastructure Stack)*. Последовательный нисходящий стек прохождения сетевого запроса: Route 53 (DNS CNAME) -> Amazon CloudFront Edge (SSL-сертификат ACM в регионе us-east-1) -> Cognito Hosted UI Engine (сессии и брендинг) -> Редирект в SPA.
     - `ru/05.html` · **Схема 6. Корпоративная и социальная федерация: интеграция SAML 2.0 и OIDC с JIT** · *Топология: мост федерации с конвергенцией потоков (Fork-Join Bridge)*. Два внешних источника (корпоративный SAML 2.0 IdP и социальный OIDC) сходятся в единый брокер федерации Cognito для маппинга claims и JIT-провижининга в локальный каталог User Pool.
     - `ru/06.html` · **Схема 7. Жизненный цикл бессерверных триггеров AWS Lambda в User Pool** · *Топология: топология «Звезда» / шина событий (Hub-and-Spoke Event Bus)*. Центральное ядро User Pool Hub соединено четырьмя радиальными двунаправленными связями с триггерами: Pre Sign-up (сверху), Pre-Token Generation (слева), Custom Message (справа) и Post Confirmation (снизу).
     - `ru/07.html` · **Схема 8. Обмен токенов на временные учетные данные AWS STS через Identity Pool** · *Топология: 4-ступенчатая цепочка делегирования (Stepwise Delegation Chain)*. Четкий конвейер обмена полномочий: ID Token -> Identity Pool GetId -> AWS STS AssumeRoleWithWebIdentity -> Прямой доступ к ресурсам AWS по подписи SigV4.
     - `ru/08.html` · **Схема 9. Эшелонированная защита каталога: интеграция AWS WAFv2 и Cognito ASF** · *Топология: многоуровневая воронка безопасности (Multi-Stage Funnel)*. Входящий трафик фильтруется сначала на уровне L7 через AWS WAFv2 (Bot Control, Rate Limiting), затем на уровне CIAM через Cognito ASF (адаптивный риск), после чего развилка направляет пользователя либо на Step-Up MFA, либо на безусловную блокировку.
     - `ru/09.html` · **Схема 10. Модель тарификации MAU, защита от SMS Toll Fraud и квоты API** · *Топология: пирамида экономики и квот (Economics Pyramid)*. Широкое основание бесплатного уровня 50K MAU сужается до квот API Identity Provider, разветвляется на защиту от SMS Fraud и TOTP аутентификаторы ($0 затрат) и завершается контролем совокупной стоимости владения TCO.
     - `ru/10.html` · **Схема 11. Базовая инфраструктура User Pool в Terraform и SRP-аутентификация** · *Топология: криптографическая лестница рукопожатия (SRP Sequence Ladder)*. Пошаговый обмен без передачи открытого пароля между клиентом и сервером: передача открытого ключа SRP_A, возврат Salt и SRP_B, передача математического доказательства HKDF и выдача токенов.
     - `ru/11.html` · **Схема 12. Сетевая интеграция: авторизаторы API Gateway, правила ALB и микросервисы** · *Топология: веерная сервисная маршрутизация (Gateway Fan-Out)*. Входящий запрос с токеном валидируется сетевым Authorizer на API Gateway / ALB, после чего веерно распределяется по целевым микросервисам (AWS Lambda, Amazon ECS, Amazon EKS) с инъекцией заголовка X-Amzn-Oidc-Data.
     - `ru/12.html` · **Схема 13. Системные потоки IGL: Passkeys FIDO2, Custom Auth и миграция пользователей** · *Топология: беспарольная лестница WebAuthn (Passkeys Protocol Ladder)*. Четырехшаговый цикл FIDO2: DEFINE_AUTH_CHALLENGE -> Возврат WebAuthn Nonce на клиент -> Локальная биометрия и подпись -> VERIFY_AUTH_CHALLENGE_RESPONSE и выпуск сессии.
     - `ru/13.html` · **Схема 14. Структура квалификационного ассессмента Noob: карта 50 вопросов** · *Топология: ступенчатая дорожная карта (Stepping Stones Roadmap)*. Пять последовательных шагов освоения фундаментальных основ (Каталог -> Токены -> PKCE -> Hosted UI -> Базовый API) с выходом на статус Инженер Noob.
     - `ru/14.html` · **Схема 15. Структура квалификационного ассессмента Pro: карта 50 вопросов** · *Топология: матрица 2х2 с интеграционным хабом (2x2 Matrix with Integration Hub)*. Четыре квадранта инженерных тем (Триггеры, IdP Федерация, STS Роли, Защита WAFv2/ASF) конвергируют в промышленный блок Terraform IaC и сетевую интеграцию с ALB.
     - `ru/15.html` · **Схема 16. Структура квалификационного ассессмента IGL: карта 50 архитектурных кейсов** · *Топология: распределенная мультирегиональная сеть (Active-Active Mesh)*. Два независимых региона (us-east-1 и eu-west-1) с двунаправленной асинхронной синхронизацией событий через DynamoDB Global Tables и фоновый репликатор для достижения архитектуры Zero-RTO.
     - `ru/navigator.html` · **Схема 17. Матрица девяти сквозных инженерных линз вокруг ядра Amazon Cognito** · *Топология: радиальная сетка 3х3 (Radial 3x3 Matrix)*. Девять канонических инженерных линз симметрично организованы вокруг центрального ядра Amazon Cognito (Components, Code, Strength, Limits, Ecosystem, AI, Cloud, DevOps, SRE).
